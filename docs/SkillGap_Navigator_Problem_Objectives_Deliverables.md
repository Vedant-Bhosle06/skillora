# SKILLORA — Problem Statement, Objectives & Deliverables
### Skill-Gap Navigator

---

## Problem Statement

Career and upskilling guidance available to most students and early-career professionals today is generic and disconnected from their actual starting point. Platforms and career counsellors typically respond to "I want to become a Data Analyst" with a broad, one-size-fits-all list of skills to learn, without accounting for what the individual already knows, how those existing skills relate to the target role, or which sequence of learning would get them there fastest. This creates two concrete problems: first, learners waste time relearning skills they already possess or learning skills in an inefficient order that ignores prerequisite relationships (e.g., attempting to learn machine learning before basic statistics); second, learners have no way to compare multiple viable paths toward a goal and choose the one that best fits their time constraints, existing strengths, or the current job market demand for the skills along the way. This problem is compounded by the fact that skills are not independent — many have prerequisite or co-requisite relationships, and some requirements can be met in more than one way (e.g., *Tableau* or *Power BI* both satisfy a role's "BI tool" requirement). The "distance" between a person's current skill set and a target role's requirement can therefore be modeled as a structured, navigable space rather than a flat checklist. SKILLORA addresses this by representing skills and their interrelationships as a knowledge graph and applying weighted graph-search algorithms (A* / Dijkstra) to compute an optimized, personalized upskilling path from a user's current competencies to a chosen target role, rather than offering generic, undifferentiated advice.

---

## Objectives

**1. Model skills and their relationships as a structured knowledge graph.** The first objective is to design and construct a skills knowledge graph in which each node represents a distinct skill (e.g., "Python", "SQL", "Statistics", "Machine Learning") carrying an estimated learning effort (in hours) and a market-demand score (the share of sampled job postings that mention the skill). Edges represent meaningful relationships between skills — most importantly "prerequisite of" (which may be mandatory, or one-of-several alternatives) and "commonly co-required with". This graph forms the structural backbone that every other objective depends on, so building it with reasonably accurate, curated data (manually curated for an initial 80–120 skill nodes rather than scraped at scale) is treated as a first-class objective in its own right, not a preliminary step.

**2. Capture a user's current skill profile and desired target role.** The system must allow a user to input their existing skills (selected from the graph's vocabulary, with self-assessed proficiency levels) and select a target job role from a curated set of role definitions, where each role is expressed as a set of skill requirements — some mandatory, some satisfiable by any one of several alternative skills. This objective focuses on designing a usable, low-friction input flow, since the quality of the recommendation depends entirely on accurately capturing where the user currently stands.

**3. Compute an optimized, minimum-effort learning path using weighted shortest-path search.** Given a user's current skill set and a target role's requirements, the system must compute the most efficient sequence of skills to learn next. This is modeled as a weighted shortest-path problem over a *state space*, where each state is the set of skills the user would hold, each move is "learn one skill whose prerequisites are already met", the move cost is that skill's learning effort, and the goal is any state that satisfies every requirement of the role. The search uses A* with an admissible heuristic (with Dijkstra's algorithm as the zero-heuristic baseline). This is the core algorithmic objective of the project: the system should not simply list all skills the target role requires, but should compute the plan that respects prerequisite ordering, reuses skills the user already has, and makes the cheapest choices wherever alternatives exist.

**4. Generate and rank multiple alternative paths, not just a single shortest path.** In many cases, more than one reasonable route exists to the same target role (for example, a path through *Tableau* versus one through *Excel → Power BI*). The system should surface a small set of near-optimal, genuinely different alternative paths and rank them using a composite cost function that combines normalized learning time with the market demand of the skills involved, giving the user meaningful choice rather than a single prescriptive answer.

**5. Present the recommended path and progress tracking through an intuitive, visual interface.** Beyond the algorithmic core, an objective of the project is to make the resulting path genuinely usable: presenting it as a clear, ordered visual roadmap (not a raw list), allowing the user to mark skills as completed and have the system recompute and re-rank remaining paths accordingly, and visualizing the underlying skill graph itself so users can understand *why* a particular sequence was recommended rather than treating the system as a black box.

**6. Validate the system's recommendations against realistic scenarios.** A final objective is to evaluate whether the computed paths are actually sensible and efficient — by defining a small number of representative "current skills → target role" test scenarios, manually reasoning about what a competent human career advisor would recommend, and comparing that against the system's output. The computed path's total learning cost is also benchmarked against a naive *generic roadmap* baseline (every skill the role requires, plus all of their prerequisites, learned from scratch in no particular order and ignoring what the user already knows) to produce a concrete, quantifiable measure of improvement.

## Deliverables

**1. A curated skills knowledge graph dataset.** The project will deliver a structured, versioned dataset — maintained as JSON seed files and loaded into MongoDB by a seed script — containing skill nodes (with learning-effort hours and market-demand scores), their prerequisite/co-requisite edges (including one-of-several prerequisite groups), and a set of target job roles expressed as skill requirements. This dataset is a standalone artifact of value independent of the application itself, and will be documented with the sourcing/curation methodology used to build it.

**2. A working full-stack web application (MERN).** The primary deliverable is a deployed, functioning web application built on MongoDB, Express, React, and Node.js, allowing a user to register/log in, build a profile of current skills with proficiency levels, browse and select a target role, and receive a computed upskilling roadmap through the interface. This includes standard supporting functionality: authentication, profile management, and a persistent record of a user's progress over time.

**3. A path-computation microservice implementing the core graph algorithms.** A dedicated backend service (implemented in Python with FastAPI, using NetworkX for graph storage and traversal, and exposed via a REST API consumed by the Node backend) implementing the A* state-space search, alternative-path generation and ranking, and supporting graph checks (cycle detection, prerequisite-order validation). It is delivered as a separable, independently testable component with its own unit tests, so the algorithmic core can be evaluated and demonstrated on its own terms, separate from the web application around it.

**4. An interactive visual roadmap and skill-graph explorer.** A frontend module that renders the recommended learning path as a clear, ordered visual sequence, and separately allows the user to explore the underlying skill graph (via a force-directed graph visualization) to see how skills relate to one another and understand the reasoning behind a given recommendation, rather than presenting the algorithm as an opaque black box.

**5. Progress tracking and path recomputation feature.** A feature allowing users to mark skills as completed as they progress, with the system recomputing and re-ranking the remaining path in response — demonstrating that the system is a living tool for ongoing guidance rather than a one-time report.

**6. An evaluation report with quantified benchmarking results.** A written evaluation comparing the system's computed paths against the generic-roadmap baseline and against hand-reasoned expert paths across the defined test scenarios. It reports concrete metrics: total estimated learning time saved, number of redundant skills avoided, prerequisite-ordering violations (system vs. baseline), overlap with the expert path, and search efficiency (states expanded by A* vs. Dijkstra). It also discusses the limitations of the graph-curation method and possible directions for scaling the skills dataset. This deliverable is what turns the project from a working app into one with a measurable, evidence-backed technical contribution.

**7. Project documentation.** Standard accompanying documentation: system architecture diagram (including the MERN app layer and the Python algorithm microservice), database/graph schema documentation, API documentation for both services, and a user guide — delivered as part of the final project report.
